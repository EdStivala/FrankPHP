title: "Getting Email Up and Running"
description: "Set up FrankPHP's email, check it works, and change the wording of the emails it sends."
---

FrankPHP has no passwords: everyone signs in with a code sent by email. **If email isn't working, nobody can sign in** — including you. This page sets it up, checks it, and shows how to put the emails in your own words.

---

## The emails FrankPHP sends

| Email | Sent to | When | Subject |
|---|---|---|---|
| **Sign-in code** | The person signing in | They ask for a code at `/login` | Your sign-in code |
| **Invite** | The person invited | An owner or platform user invites them | You've been invited |
| **New sign-up alert** | You, at `MAIL_SITE_ADMIN` | Someone new asks for a code, and again when their account is created | New Signup Alert |

<Warning>
**Transactional email only.** FrankPHP's email is built for messages people need, like codes and invites. It isn't made for newsletters or bulk marketing.
</Warning>

---

## Set up your mail settings

Your mail settings live in `app/.env`, which you filled in at [Step 2](/getting-started/step-2). You'll need these from your email provider — your hosting company's mail server, or a service such as Postmark, Mailgun or Amazon SES:

- **`MAIL_HOST`** and **`MAIL_PORT`** — the provider's SMTP server and port
- **`MAIL_USERNAME`** and **`MAIL_PASSWORD`** — your SMTP login
- **`MAIL_FROM_ADDRESS`** and **`MAIL_FROM_NAME`** — who the emails come from
- **`MAIL_REPLY_TO`** — where replies go
- **`MAIL_SITE_ADMIN`** — your own address, for the sign-up alerts

Every key, with its default, is in [Environment Configuration](/architecture/environment-configuration#email).

<Tip>
Send from an address on your own domain, and set up the SPF and DKIM records your provider asks for. Emails are much less likely to land in spam.
</Tip>

## Check it works

<Steps>
  <Step title="Ask for a sign-in code">
    Go to `/login`, enter an email address you can read, and select **Email me a code**.
  </Step>
  <Step title="Check your inbox">
    The code should arrive shortly. Type it in to sign in.
  </Step>
  <Step title="Check the alerts">
    If the address was new, `MAIL_SITE_ADMIN` gets two **New Signup Alert** emails: one when the code was asked for, and one when the account was created.
  </Step>
  <Step title="Try an invite (optional)">
    As an owner, open the **User Screen**, select **Invite**, and invite another address you can read.
  </Step>
</Steps>

<Check>
If the code arrives, email is working, and anyone can sign in.
</Check>

<Note>
**No code arriving?** Check your spam folder first. Then check each `MAIL_` setting in `app/.env` against your provider's details: the server, port, username and password must all match exactly.
</Note>

## Put the emails in your own words

Each email's wording comes from a template class in `framework/Services/Email/Templates/`.

<Warning>
**Never edit those templates directly.** They're in `framework/`, so an update replaces them and your changes are lost. Replace the template from your own side instead.
</Warning>

<Steps>
  <Step title="Write your own template class">
    It needs the same two functions, with the same arguments, as the one it replaces. For the sign-in code:

    ```php
    // app/Email/Templates/MyLoginCodeTemplate.php
    namespace App\Email\Templates;

    class MyLoginCodeTemplate
    {
        public static function buildHtml(string $email, string $code, int $expiry): string
        {
            return '<p>Your code for My App is <strong>' . htmlspecialchars($code) . '</strong>.</p>'
                 . '<p>It lasts ' . $expiry . ' minutes.</p>';
        }

        public static function buildText(string $email, string $code, int $expiry): string
        {
            return "Your code for My App is {$code}. It lasts {$expiry} minutes.";
        }
    }
    ```

    The class can live anywhere under `App\`.
  </Step>
  <Step title="Name it in your config">
    In `app/Config/config.php`, add it to `templates` inside the `mail` settings:

    ```php
    'mail' => [
        // ...the existing keys...
        'templates' => [
            'login_code' => \App\Email\Templates\MyLoginCodeTemplate::class,
        ],
    ],
    ```
  </Step>
</Steps>

Each email has its own key, and its template needs these two functions:

| Email | Key | Its two functions |
|---|---|---|
| Sign-in code | `login_code` | `buildHtml(string $email, string $code, int $expiry)` and `buildText(…)` with the same arguments. `$expiry` is in minutes. |
| Invite | `invite` | `buildHtml(string $email, string $inviteUrl, int $expiryDays)` and `buildText(…)` |
| New sign-up alert | `platform_owner_signup_alert` | `buildHtml(string $email, string $event)` and `buildText(…)` |

Both functions return the email's content as a string. The subject lines stay as they are.

<Info>
The sign-in code email must carry the code only — never a link.
</Info>

## Sending your own emails

For emails of your own, such as an invoice, write a service of your own that hands its message to FrankPHP's `EmailService`. See [Sending your own kind of email](/architecture/dependency-injection#sending-your-own-kind-of-email).
