# Upgrading to 2.2.0

FrankPHP 2.2.0 lets platform users see every tenant's users on the Users dashboard, and hides the Users links from the `user` role. There are **no database or route changes**. Follow these steps on each existing install. New installs need none of this.

<Note>
**Coming from 2.1.0 or earlier?** Check that `app/public/index.php` uses these two lines before you replace `framework/`. Since v2.1.1 the framework stops with an error if they're wrong.

```php
define('APP_BASE_DIR', dirname(__DIR__, 2));
require_once APP_BASE_DIR . '/framework/bootstrap.php';
```

Coming from 2.0.x, also follow [Upgrading to 2.1.0](/users/upgrading-to-2-1-0) first. It includes a database migration.
</Note>

---

<Steps>
  <Step title="Replace the framework/ folder">
    Replace your `framework/` folder with the 2.2.0 release, as for any update. No database migration is needed.
  </Step>
  <Step title="Update your app's views">
    The new Tenant column and the hidden Users links are in your app's views. These files belong to your app, so the framework update doesn't change them. Copy these changes in.

    **`app/Views/users/management-dashboard.php`**: show the tenant when the list spans all tenants. The page receives `$crossTenant` (true or false), and each user row has a `tenantName`.

    ```php
    <p class="text-muted mb-0" style="font-size:0.8125rem;"><?= $crossTenant ? 'All tenants' : htmlspecialchars($tenant['name'] ?? '') ?></p>
    ...
    <th>Name</th>
    <?php if ($crossTenant) : ?><th>Tenant</th><?php endif; ?>
    ...
    <td><?= htmlspecialchars($row['name']) ?></td>
    <?php if ($crossTenant) : ?><td><?= htmlspecialchars($row['tenantName']) ?></td><?php endif; ?>
    ```

    **`app/Views/partials/app-nav.php`** (the sidebar **Users** link) and **`app/Views/partials/app-header.php`** (the **Manage Users** link and the divider above it): wrap each one so the `user` role doesn't see it.

    ```php
    <?php if (in_array($user['role'] ?? '', ['platform', 'admin', 'owner'], true)) : ?>
        ... the Users / Manage Users link ...
    <?php endif; ?>
    ```

    <Note>
    If you skip this step, the page still works. Platform users see every tenant's users, but without the Tenant column. The `user` role still sees the links, and is refused on click.

    If you copy in the `management-dashboard.php` change and your app overrides `UserManagementController`, also do the override step below. Otherwise the page gives undefined-variable warnings.
    </Note>
  </Step>
  <Step title="Only if your app builds UserManagementService itself">
    Most apps don't, and the framework's own setup already does this. If your `app/bootstrap.php` creates `UserManagementService` itself, pass the tenant model too:

    ```php
    new \Frank\Services\UserManagementService(
        userModel: new \Frank\Models\User(),
        tenantModel: new \Frank\Models\Tenant(),
    );
    ```
  </Step>
  <Step title="Only if your app overrides UserManagementController">
    If your `app/bootstrap.php` replaces `UserManagementController` using `$container->override()`, and your subclass defines its own `index()`, the framework's `index()` no longer runs. The new `crossTenant` value then never reaches the view. Add this line to the view params your `index()` passes. It's copied from the framework's `UserManagementController.php`, line 57, where `$result` is what `getUserDashboard()` returns:

    ```php
    'crossTenant'        => $result->get('crossTenant', false),
    ```

    This is the only view param added in 2.2.0. Without it, the updated `management-dashboard.php` reads an undefined `$crossTenant`. PHP gives undefined-variable warnings, and platform users see the current tenant's name instead of "All tenants", with no Tenant column.
  </Step>
</Steps>

---

## Check it worked

- **Log in as a platform user:** Users lists people from several tenants, with a Tenant column.
- **Log in as an owner or admin:** Users lists your own tenant only.
- **Log in as a user:** there's no Users link, and visiting `/tenant/{id}/users` sends you back with `?error=forbidden`.
