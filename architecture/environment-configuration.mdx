FrankPHP keeps every setting that changes from one install to another — database details, mail credentials, sign-in keys — in one plain text file: `app/.env`. Your code never holds them. It reads them, through `app/Config/config.php`, every time a page loads.

---

## Why a `.env` file

- **Better security.** Your credentials live outside the public web folder and outside your code, so they can't be requested in a browser, and they don't end up in your source history or a release by accident.
- **Cleaner deployments.** Your laptop, a staging server and the live site each have their own `.env`. The code is identical everywhere; only the file differs.
- **A familiar workflow.** Laravel, Symfony and most other PHP frameworks work the same way, so developers coming from them will recognise it straight away.

FrankPHP does this without any outside package: a small loader of its own, `Frank\Core\Env`, reads the file.

---

## Where the files live

```text
/yourproject
  /framework       ← replaced on every update
  /app
    .env           ← your settings and secrets
    env.example    ← the template
    /Config
      config.php   ← reads .env
    /public        ← all the web can see
      index.php
```

You create `app/.env` by copying `app/env.example` and filling in your own values, as in [Step 2 of Get FrankPHP Running](/getting-started/step-2).

## Every key

**Required** keys must be present and not empty, or no page loads. A required key can hold a placeholder until you need it to work. Optional keys can be left out; FrankPHP then uses the default shown.

### Application

| Key | Required | What it's for |
|-----|----------|---------------|
| `APP_NAME` | No — default `FrankPHP App` | Your app's name. Also the sender name on emails, unless `MAIL_FROM_NAME` is set. |
| `APP_TIMEZONE` | No — default `UTC` | The app's timezone, used when neither the user nor the tenant has one set. |

### Database

| Key | Required | What it's for |
|-----|----------|---------------|
| `DB_HOST` | Yes | The database server, almost always `localhost` on shared hosting. |
| `DB_PORT` | No — default `3306` | The database port. |
| `DB_NAME` | Yes | The database name. |
| `DB_USER` | Yes | The database username. |
| `DB_PASS` | Yes | The database password. |

### Email

FrankPHP has no passwords: everyone signs in with a code sent by email, so these must work before anyone can sign in. See [Getting Email Up and Running](/getting-started/getting-email-up-and-running).

| Key | Required | What it's for |
|-----|----------|---------------|
| `MAIL_HOST` | Yes | Your mail provider's SMTP server. |
| `MAIL_PORT` | No — default `587` | The SMTP port. |
| `MAIL_USERNAME` | Yes | The SMTP username. |
| `MAIL_PASSWORD` | Yes | The SMTP password. |
| `MAIL_FROM_ADDRESS` | Yes | The address emails are sent from. |
| `MAIL_FROM_NAME` | No — default `APP_NAME` | The sender name people see. |
| `MAIL_REPLY_TO` | No — default `MAIL_FROM_ADDRESS` | Where replies go. |
| `MAIL_SITE_ADMIN` | Yes | Your own address. FrankPHP emails it when someone new requests a sign-in code and when their account is created. |

### Google and Microsoft sign-in

| Key | Required | What it's for |
|-----|----------|---------------|
| `GOOGLE_CLIENT_ID` | No | With `GOOGLE_CLIENT_SECRET`, turns on the **Continue with Google** button on the sign-in screen. Leave both empty to keep it off. |
| `GOOGLE_CLIENT_SECRET` | No | See `GOOGLE_CLIENT_ID`. |
| `MICROSOFT_CLIENT_ID` | No | Not used yet. Microsoft sign-in is planned for a future release; setting it turns nothing on. |
| `MICROSOFT_CLIENT_SECRET` | No | As `MICROSOFT_CLIENT_ID`. |

### Other

| Key | Required | What it's for |
|-----|----------|---------------|
| `CRON_SECRET` | Yes | A long random secret for scheduled jobs. Nothing in the framework reads it yet. |
| `SYNCFUSION_LICENSE_KEY` | Yes | Your Syncfusion licence key, if you use their components. It is sent to the browser, so anyone signed in can see it in the page source. |

## How FrankPHP reads the file

Before anything else happens, `framework/bootstrap.php` calls `Env::load()` on `app/.env` (step 1 of [The Run Cycle](/architecture/the-run-cycle)). Then `app/Config/config.php` picks out each value and builds the settings the rest of FrankPHP uses.

The file is simple `KEY=value` lines:

```dotenv
# A whole line starting with # is a comment
APP_NAME="My App"          # quotes are optional, and are removed
DB_PASS=abc==def           # everything after the first = is the value
```

- If `app/.env` doesn't exist, FrankPHP stops with a message saying so.
- If a required key is missing or empty, FrankPHP stops with a message naming the key.
- If the server already sets a variable with the same name, the server's value wins and the line in `.env` is ignored.

## Adding your own setting

1. Add the key to `app/env.example`, with a placeholder value.
2. Add it, with the real value, to your `app/.env`.
3. Read it in `app/Config/config.php` with `Env::get('YOUR_KEY', 'default')`, or with `Env::require('YOUR_KEY')` if there is no sensible default.

---

## Keeping `.env` private

- **Never in the public folder.** `app/.env` sits outside `app/public/`, the only folder your web server should point to. See [Step 5 of Get FrankPHP Running](/getting-started/step-5).
- **Never in git.** `app/.env` is listed in the project's `.gitignore`, so it isn't committed. Commit `app/env.example` instead.
- **Never in a release.** The framework-only release zip contains `framework/` alone, and the build script also skips any `.env` file it finds.

<Warning>
Treat `app/.env` like a password. Don't paste it into support requests, chats or AI assistants; share `app/env.example` instead.
</Warning>
