Most controllers need a service or two — the email sender, the customer service. Rather than each controller building its own, FrankPHP builds each service **once, in one place**, and hands it to whoever needs it. That's dependency injection. The place it happens is called the **container**.

---

## Why FrankPHP does it this way

In Laravel or Symfony, the container works out what to build by inspecting your code. It's convenient, but it happens out of sight.

FrankPHP's container works nothing out for itself. **Every service is built by a few lines of plain PHP you write yourself**, in a `bootstrap.php` file. If you want to know how something is built, or what it's given, you can read it — and so can your AI assistant.

The container itself is one short file, `framework/Core/Container.php`, with no hidden machinery.

## The container's methods

| Method | What it does | Use it for |
|---|---|---|
| `singleton($id, $recipe)` | Builds it once, then hands out that same one every time | Services |
| `bind($id, $recipe)` | Builds a fresh one every time it's asked for | Controllers |
| `override($id, $recipe)` | Replaces a recipe that's already registered | Deliberately changing framework behaviour |
| `make($id)` | Gets one, built by its recipe | Inside a recipe, to fetch another service |
| `has($id)` | Says whether a recipe is registered | — |

A recipe is a small function that returns the built object. It's given the container, as `$c`, so it can `make()` anything else it needs.

<Note>
Registering the same thing twice with `singleton()` or `bind()` stops with an error, so nothing can be replaced by accident. To replace something on purpose, use `override()`.
</Note>

## Adding your own

This uses the Customer Record from [Add a form](/cookbooks/add-a-form). Everything goes in `app/bootstrap.php`.

<Steps>
  <Step title="Register the service">
    ```php
    $container->singleton(\App\Services\CustomerService::class, function ($c) {
        return new \App\Services\CustomerService();
    });
    ```

    If your service needs something, build it in here. For example, `$c->make(\Frank\Services\Email\EmailService::class)` hands it the framework's email sender.
  </Step>
  <Step title="Register the controller">
    ```php
    $container->bind(\App\Controllers\CustomerController::class, function ($c) {
        return new \App\Controllers\CustomerController(
            $c->make(\App\Services\CustomerService::class)
        );
    });
    ```
  </Step>
  <Step title="Ask for it in the controller">
    ```php
    public function __construct(private CustomerService $customerService) {}
    ```
  </Step>
  <Step title="Add the route as normal">
    ```php
    $router->add('GET', '/tenant/{tenant_id}/customers', 'CustomerController@index', [$tm, $auth]);
    ```

    Nothing about the route changes. The router finds your recipe and uses it.
  </Step>
</Steps>

<Tip>
- **Models never need registering.** Create them with `new` — they connect to the database by themselves.
- **Controllers with nothing to hand over** don't need registering either.
- **Middleware can't be registered.** FrankPHP creates it with `new` and passes nothing in. See [Middleware](/concepts/middleware#writing-your-own).
- **Record every service you register** in `app/MYAPP.md`: what it is, what it's given, and whether it's a `singleton` or a `bind`.
</Tip>

## The framework's own services

`framework/bootstrap.php` registers these before your `app/bootstrap.php` runs, so you can `make()` any of them in your own recipes:

| Service | What it does |
|---|---|
| `EmailService` | Sends email. The only place that knows your mail settings. |
| `LoginCodeService` | Signing in with an emailed code |
| `GoogleSignInService` | Continue with Google |
| `AccountService` | Creates every new account |
| `InviteService` | Invites |
| `UserService` | Operations on users |
| `TenantService` | Operations on tenants |
| `SignupTenantResolver` | Decides where new people go — **meant to be replaced** if your app needs a different rule |

<Warning>
Don't change the framework's recipes in `framework/bootstrap.php`: an update replaces that file. If you need different behaviour, replace the recipe from your own side with `override()`.
</Warning>

## Replacing a framework service

From `app/bootstrap.php`, `override()` swaps a framework recipe for your own:

```php
$container->override(\Frank\Services\SignupTenantResolver::class, fn ($c) =>
    new \App\Services\MyTenantRule()
);
```

It's deliberate and visible, never an accident. For a full example, see [Send New People Somewhere Else](/cookbooks/send-new-people-elsewhere). Routes work the same way: `$router->override()` replaces a framework route.

## Sending your own kind of email

`EmailService` sends the framework's own emails. To send one of yours — an invoice, say — don't add to `EmailService`: it's in `framework/`, so your change would be lost on the next update. Write a service of your own that builds the message and hands it to `EmailService::send()`:

```php
// app/Services/NotificationService.php
namespace App\Services;

use Frank\Services\Email\EmailMessage;
use Frank\Services\Email\EmailResult;
use Frank\Services\Email\EmailService;

class NotificationService
{
    public function __construct(private EmailService $emailService, private array $mail) {}

    public function sendInvoice(string $email, string $name, string $html): EmailResult
    {
        return $this->emailService->send(new EmailMessage(
            credentialsUserName:   $this->mail['username'],
            credentialsUserSecret: $this->mail['password'],
            to:                    $email,
            subject:               'Your invoice',
            htmlBody:              $html,
            from:                  $this->mail['from_address'],
            fromName:              $this->mail['from_name'],
            toName:                $name,
            replyTo:               $this->mail['reply_to'],
        ));
    }
}
```

And its recipe, which hands it the email sender and your mail settings:

```php
$container->singleton(\App\Services\NotificationService::class, function ($c) use ($config) {
    return new \App\Services\NotificationService(
        $c->make(\Frank\Services\Email\EmailService::class),
        $config['mail']
    );
});
```
