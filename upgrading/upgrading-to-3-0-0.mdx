---
title: "Upgrading to 3.0.0"
description: "Upgrade an existing FrankPHP install from 2.2 to 3.0.0: the passwordless migration, the app changes it needs, and the optional new features."
---

FrankPHP 3.0.0 removes passwords: one screen signs people in with an emailed 6-digit code. **This is a breaking release.** The database must be migrated, routes are removed and added, and some files in `app/` must change. Follow these steps on each existing install. New installs need none of this.

<Warning>
**Run the migration when you deploy.** Unlike earlier releases, the 3.0.0 code doesn't work on a database that hasn't been migrated. Back up first.
</Warning>

<Note>
**Coming from 2.1 or earlier?** Follow [Upgrading to 2.2.0](/upgrading/upgrading-to-2-2-0) first.
</Note>

---

## What changes

| Area | 2.2 | 3.0.0 |
|---|---|---|
| Signing in | Passwords, a two-step `/signup`, forgot and reset password | One screen at `/login`, with an emailed code. Optional Continue with Google. |
| Email addresses | Unique within a tenant | Unique across the whole site: one email, one user, one tenant |
| Staying signed in | PHP's default session | 28 days, renewed while the person keeps using the app |
| The User Screen | Part of the framework | Part of your app |
| New | — | Invites, and support access for platform users |

## Before you deploy

<Steps>
  <Step title="Back up the database">
    The migration removes passwords and two tables. There's no way back without a backup.
  </Step>
  <Step title="Find duplicate email addresses">
    One email address can now belong to only one user. List any that are used more than once:

    ```sql
    SELECT email, COUNT(*) FROM users GROUP BY email HAVING COUNT(*) > 1;
    ```

    Resolve each one by hand — delete one of the users, or change their address. The migration stops at its first step if any duplicates remain.
  </Step>
</Steps>

---

## Deploy and migrate

<Steps>
  <Step title="Replace the framework/ folder">
    Replace `framework/` with the 3.0.0 framework-only zip, as for any update. Leave `app/` untouched.
  </Step>
  <Step title="Run the migration">
    Run this script against each environment's database:

    ```text
    framework/sql/migrations/v3.0.0_passwordless.sql
    ```

    It makes email addresses unique, creates the `login_codes` and `invites` tables, then removes `users.password_hash` and the `password_reset_tokens` and `signup_tokens` tables. **Nobody can sign in with a password after this.**
  </Step>
</Steps>

## Update your app

These changes are in your own `app/`, so an update can't make them for you. Copy files from the 3.0.0 starter app — the release's Source code zip — where a step says so.

<Steps>
  <Step title="Swap in the new sign-in screens">
    Copy `login.php`, `login-verify.php` and `login-terms.php` into your `app/Views/auth/`.

    Delete the old screens: `signup.php`, `signup-verify.php`, `forgot-password.php`, `forgot-password-sent.php`, `reset-password.php` and `reset-password-error.php`. Remove any link or wording in your own views about passwords, "forgot password" or `/signup` — `/signup` now gives "not found".
  </Step>
  <Step title="Start sessions the new way">
    In `app/public/index.php`, replace the `session_start()` block with:

    ```php
    \Frank\Core\Session::start();
    ```
  </Step>
  <Step title="Let the server create the sessions folder">
    Make sure the web server can create `app/private/sessions`. Everyone is signed out once, because sessions move to this new folder.
  </Step>
  <Step title="Add the security token to your settings forms">
    Account and tenant settings now refuse a form without the security token. Add this inside both forms, or they stop saving:

    ```php
    <?php include APP_VIEWS_DIR . '/partials/csrf-field.php'; ?>
    ```

    If you have your own copies of any sign-in screens, use the same line in place of their old `$csrfToken` hidden field.
  </Step>
  <Step title="Rename email template overrides">
    In `app/Config/config.php`, a `mail.templates` override named `signup_verification` becomes `login_code`, with the same functions. `password_reset` is no longer used.
  </Step>
  <Step title="Copy in the User Screen, if you use it">
    The User Screen moved from the framework into the starter app. Copy `app/Controllers/UserManagementController.php`, `app/Services/UserManagementService.php`, the `GET /tenant/{tenant_id}/users` route, and the two container recipes for them from the starter app's `app/bootstrap.php`.
  </Step>
  <Step title="Check your own / route, if you have one">
    Make it send a signed-in person to their dashboard using `[$auth]` only, not `[$tm, $auth]` — as the starter app's `HomeController@root` does. Otherwise visiting `/` signs people out.
  </Step>
  <Step title="Check for getBaseUrl() and updated_at">
    - Replace any call to `EmailService::getBaseUrl()` with `\Frank\Core\Url::baseUrl()`.
    - `save()` now writes `updated_at` back as it was loaded. If one of your tables relies on MySQL's `ON UPDATE CURRENT_TIMESTAMP`, set `updated_at` yourself in your service, with `Clock::nowUtcString()`, before calling `save()`.
  </Step>
</Steps>

## Optional: the new features

<AccordionGroup>
  <Accordion title="Invites">
    Copy `invite-welcome.php` and `invite-expired.php` into your `app/Views/auth/`. Sending invites is up to your app: the starter app's User Screen, `UserAdminController@sendInvite` and its route are a worked example.
  </Accordion>
  <Accordion title="Continue with Google">
    1. Add the four `GOOGLE_*` and `MICROSOFT_*` keys from `app/env.example` to your `app/.env`. Empty is fine; the Microsoft ones do nothing yet.
    2. Add the `oauth` section to your `app/Config/config.php`.
    3. Use the new `app/Views/auth/login.php`, which has the Google button.
    4. To turn it on, register your app with Google, add `{your site}/login/google/callback` exactly as an authorised redirect address, and put the client ID and secret in `app/.env`.
  </Accordion>
  <Accordion title="Support access">
    The framework's routes are there for every app; the screens are yours. To use the starter app's, copy:

    - the Capture Tenant form from `app/Views/users/tenant-edit.php`
    - the `Session::supportAccess()` block from `app/Views/partials/app-header.php`
    - the `topbar--support` class on the `<header>` in `app/Views/layouts/app-main.php`
    - the `.topbar--support` rules from `app/public/assets/css/app-header.css`
  </Accordion>
</AccordionGroup>

## Check it worked

<Check>
- **Sign in with an existing address:** the code arrives, and the right code takes you to your dashboard.
- **Sign in with a new address:** a new tenant is created, with you as its owner — after the terms step, if terms are on.
- **Three wrong codes** cancel the code. `/signup` and `/forgot-password` give "not found".
- **Account and tenant settings** still save.
- **If you use them:** an invite arrives and its link opens the welcome screen; Continue with Google signs you in; Capture Tenant turns the top bar red and Release Tenant brings you back.
</Check>
